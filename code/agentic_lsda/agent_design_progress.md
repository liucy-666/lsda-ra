# MMDIT 文化绑定漂移 → Agentic 时序干预：进度总结

> 汇总时间：本轮讨论结束点。涵盖：问题定义、指标（CADS）、工具（LSDA）、Agent 架构、训练管线、实验矩阵、生死假设、待办。

## 0. 一句话现状

从"检测文化绑定漂移 + 调用 LSDA 修复"升级为：**把 MM-DiT 去噪轨迹建模为可交互环境，Agent（VLM 感知器 + 时序策略 + LSDA 工具 + 反馈验证器）在可纠正窗口内做序贯工具调用（WAIT / INVOKE / ACCEPT / ROLLBACK）的闭环系统**。CADS 从"在线每步输入"退为"离线教师信号 + 机制解释 + 验证工具"。

## 1. 问题与既有证据

- **问题**：多文化实体组合生成时属性泄漏/错误绑定（例：Chinese blue-and-white vs Japanese Kutani，右侧花瓶被青花瓷化）。发生在 MM-DiT 去噪轨迹中（28 步 / 38 层）。
- **证据**：LSDA 干预将某指标从 **51.78% → 14.11%** —— 只证明"LSDA 值得被控制"，**尚不能证明** RL / VLM / Agent 的必要性。

## 2. 已锁定的设计决策

### 2.1 工具：LSDA（局部专家扩散）
- 语义：对目标实体区域，用部分 prompt（如仅"青花瓷"）的局部专家重新注入噪声并去噪，规避多实体干扰。
- 接口：`LSDA.invoke(checkpoint=z_t, target=i, region=mask_i, strength=s) -> corrected_state`
- 代价：额外推理时间 + 结构损伤风险。
- **采用方案 B（回滚重放）**：发现异常时刻与重画起点解耦 —— Agent 在第 18 步确认漂移，可回滚到第 12 步执行 LSDA。动作变为 `INVOKE(i, rollback horizon k)`。

### 2.2 指标：CADS（文化属性漂移分数）—— 离线教师
- 构建：匹配 standalone controls（同器型 / 同 seed / 同布局，只变文化）→ 每(文化对, L, t)一条轴 `â = (μ_A−μ_B)/||·||`，中点 m。
- 定义：`CADS = clip[0.5 + (z−m)ᵀâ/||μ_A−μ_B||, 0, 1]`；0=像 B、0.5=混合、1=强 A→B 漂移（对 A 区域用反向轴，保证"1=被对方污染"语义统一）。
- 已定的打磨项：有效性掩码（||μ_A−μ_B|| 太小 → CADS:null）、(L,t) 可读性热力图、轴外残差（区分"泄漏"与"合成失败"）、trend 用未 clip 投影计算、窗口 [t_readable, t*] 静态输入、阈值跨文化对共享（0/1 锚点每对自校准）。
- **在线不再算 CADS**。动机：部署期对任意新文化对无法现场生成 controls（在线点积本身并不贵）。

### 2.3 Agent 架构：部分可观测序贯决策 M = ⟨S, O, A, T, R⟩
- 状态 S_t：完整 latent / attention / MLP / 残差流。
- 观测 O_t（三层）：
  1. 视觉预览 `I_t = D_preview(z_t)`（6–10 个决策点解码，不必每步）；
  2. 实体级指标 `x_t^i = [b, ℓ, c, m, r, q]`（绑定强度/泄漏/cross-attn 竞争/MLP 异常/残差混合/轮廓稳定度）+ 趋势 Δx；
  3. 任务条件：prompt、实体-属性图 G、log-SNR、已用工具、剩余预算。
- 动作：`a_t ∈ {WAIT, INVOKE(i,k), ACCEPT, ROLLBACK}`（v1 不学 mask 缩放/强度/步数，避免与"时机学习"混淆）。
- 转移 T：执行若干去噪步（含 LSDA 注入 / 回滚）。
- 闭环：Observe → Diagnose → Wait/Invoke → Verify → Continue/Rollback。
- 反馈：调用前后双分支（native vs LSDA）观测，学 **ΔC1（绑定收益）/ ΔC2（结构代价）反事实差值**，而非绝对质量；调用后 δ=2–4 步再验证。
- 最优停止定义：`τ_i* = inf{t : Q_invoke(O_1:t) ≥ Q_wait(O_1:t)}`。

### 2.4 奖励
- 终局：`R = w1·C_bind − w2·L_struct − w3·L_leak − w4·L_artifact − w5·C_compute`；
- 结构作**硬约束**：`max C_bind s.t. L_struct ≤ ε`（防"强行改写纹理换绑定分"）。
- 干预后局部奖励：`r_t = α·ΔC1 − β·ΔC2 − γ·Cost(a_t)`。
- 标签管线：离线 VLM+人工审计生成奖励标签 → 训练轻量 reward model → RL 主要用 reward model。

### 2.5 训练管线（不直接 RL）
- 阶段 0：离线反事实轨迹 —— 每 prompt×seed 保存多 checkpoint，在不同时刻/实体调用 LSDA，记录调用前信号、中间预览、动作、终局绑定/结构质量、成本。
- 阶段 1：监督诊断 —— 分离 **current drift（当前可见）** 与 **future risk（内部信号预示，研究价值所在）**，学三件事：当前漂移状态、未来风险、受影响实体。
- 阶段 2：Oracle 行为克隆 —— 离线算 `a^oracle = argmax U(trajectory|a)`，BC 训练 VLM/策略。
- 阶段 3：RL 微调 —— 在真实去噪环境执行动作、读干预反馈、继续决策；GRPO/PPO 可选（动作空间小时普通 actor-critic / 离线 RL 更稳；**算法不是贡献点**）。

### 2.6 工程约束
- 轻量监测器每步运行；VLM 仅在 6–10 个决策点或风险突变时唤醒；
- LSDA 后 2–4 步 cooldown；每实体 ≤1–2 次调用；整图调用预算 K；
- 每次调用前保存可复现 checkpoint：(z_t, scheduler state, RNG state, masks)。

## 3. 三条生死假设（叙事锚点）

- **H1**：内部信号能提前预测最终漂移（future risk 可测、早于视觉可见）。
- **H2**：最优干预时机确实随样本/实体变化（否则固定调度器就够）。
- **H3**：学习策略优于固定时机与简单阈值（含 oracle 蒸馏 vs RL）。

> 任一不成立 → Agent 叙事缩回"普通检测器"或"固定调度器"。
> 核心研究问题：**VLM Agent 能否根据干预前后的去噪状态，学习一个优于固定时机、阈值控制、单次调用策略的闭环 LSDA 策略？**

## 4. 实验矩阵

| 实验 | 内容 | 关键指标 |
|---|---|---|
| Exp0 | 最优时机是否样本依赖 | C1(t)–C2(t) 曲线（若时机集中 → 固定调度足够） |
| Exp1 | 内部指标能否提前预测漂移 | AUROC/AUPRC、提前量、实体定位、置信度校准、**按文化对划分**的泛化 |
| Exp2 | 时机策略对比 | step0 / 最优固定 / 随机 / 单指标阈值 / 监督分类器 / oracle 蒸馏 / RL / **离线 oracle 上界** |
| Exp3 | 模块与奖励消融 | 中间图像 / MLP 指标 / attention 泄漏 / 历史趋势 / 结构奖励 / 回滚动作 / 干预后验证器 |
| Exp4 | 系统成本与失败模式 | 调用次数、推理时间、显存、回滚长度、绑定恢复率、结构损伤率、**无干预样本上的误触发率** |
| Exp5 | VLM 必要性 | 小策略网(仅指标) vs 图像 VLM vs 图像+prompt vs 完整 Agent（若 1≈4 → VLM 非必要贡献） |
| Exp6 | 在线 vs 离线 | 交互策略(1×算力) vs 两遍式决策器(2×算力) vs 最优固定 vs oracle（准确率/质量/计算量四列对照） |

## 5. 术语锁定

| 术语 | 定义 |
|---|---|
| 文化绑定漂移 | 文化属性被错误绑定或泄漏到其他实体 |
| LSDA 工具 | 对目标实体执行局部专家重预测的可调用模块 |
| 去噪环境 | MM-DiT 轨迹、checkpoint 及内部观测组成的交互环境 |
| 漂移诊断器 | 识别当前漂移并预测未来漂移风险 |
| 时序策略 | 决定等待、调用、回滚和接受的策略 |
| Agent | 诊断—调用—验证—重规划闭环，而非单次分类器 |

## 6. 尚未定案 / 风险

1. **ROI 中途来源**：中途无 SAM → 依赖 cross-attention mask（前置依赖，需验证与 SAM 一致性；或做 global-pooled 消融）。
2. **标签成本**：每个失败轨迹的 grid 实验 ≈ 8 次全量生成（预算 ~300–500 条失败轨迹 ≈ 2.5–4K 次生成）。
3. **奖励标签质量**：reward model 需人工审计子集；标签噪声会传播到策略。
4. **误触发控制**：自愈轨迹上的不必要 LSDA 调用率必须单独报告（奖励中 −γCost 要够重）。
5. **VLM 接口**：数值指标如何文本化、离散动作如何结构化输出。
6. **held-out 平衡**：held-out 文化对必须混入"会漂移"的对，避免假泛化。
7. **CADS 轴匹配细节**：轴构建的"同器型配对"具体做法待确认（影响指标可信度）。
8. **两遍式 vs 交互式**：主设计是**交互式在线闭环**（轨迹内决策 + 回滚 + 验证）；两遍式（pass1 全跑 → 决策 → pass2 同 seed 重放）只是 Exp6 的基线。注意区分：**训练数据离线采集 ≠ 系统离线决策**——离线反事实轨迹是 RL 预热（BC warm start / experience replay），部署时 Agent 纯在线交互。回滚是轨迹内局部倒带（checkpoint z_{t-k} → LSDA → 继续向前），不是"重放完整一遍"。
9. **MM-DiT hook 接口/激活形状**未给出（如需我搭管线，需要这些）。

## 7. 下一步（建议顺序）

1. **Exp0 + H1（机制实验先行）**：CADS 可读性热力图 + "漂移可提前预测" 相关性分析 → 决定 Agent 是否值得；
2. **数据管线**：固定 seeded 投影 P、ROI pooling、grid 反事实轨迹生成；
3. **监督诊断器**：need_lsda（图像为主）+ start_step（FFN 轨迹为主，非对称结构）；
4. **蒸馏在线停止策略**（窗口 [t_readable, t*] 约束动作空间）→ 与离线/固定时机对照；
5. **RL 微调**（可选打磨，非核心贡献）。

## 8. 论证纪律（写论文时）

- 51.78%→14.11% 只支撑"LSDA 有干预潜力"，不支撑 Agent/RL/VLM 必要性；
- Agent 部分必须分别证明 H1、H2、H3；
- 任何证据分三层标注：`[data-supported]` / `[hypothesis]` / `[system design]`。
